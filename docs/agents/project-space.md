# 项目空间管理

开发依赖入口见[开发环境](dev-environment.md)。相同锁定依赖、Python 和平台复用一个仓库外的只读开发环境；生产依赖独立管理。依赖准备、验证及 Codex Actions 都使用该入口，工作树不再分别安装开发依赖。uv 下载缓存通过 uv 自身管理，不手工删除缓存内部文件。

## 材料容量

附件与实验材料的项目总预算为 3,000,000,000 字节，所有参与的开发工作树和生产材料共同计量。下载原件、下载中的临时文件、解压文件、页面图片及实验产物都计入预算。依赖、源码、Git 数据及必要的结构化审核状态单独统计。

统一私有库存位于工作树外。新实验材料使用受管入口；历史审核材料保留冻结时的原路径，登记原位置和来源后纳入计量，不为统一目录改写审核包或提交回执。开发与生产的业务运行目录继续隔离。

每次采集开始时统一发现并登记已有开发工作树和生产克隆的材料，随后在进程间互斥的容量预留中写入。已知大小先预留，未知大小的流分块检查，解压和渲染产物同样检查。并发任务不能分别使用同一份剩余空间。空间不足时，先回收已明确结束且无引用的实验产物，再回收允许重新取材的闲置本地附件副本；仍不足则拒绝新增材料，保留明确的容量失败。

## 保护与回收

正在处理或未闭合的处理尝试、写入结果未知的材料、状态无效或归属不可信的目录、活动读取或写入和恢复所需证据保持保护。Git 工作树、未提交源码和凭据不属于实验产物，不能按所在目录名或年龄自动删除。

只有能确认处理已闭合、写入结果已知且没有当前读取的本地副本，才可以因容量不足提前回收。最新已闭合尝试的材料也适用此规则，结构化状态和回执继续保留。该规则改变可回收附件副本的时间留存下限；必要的审核状态、提交回执和恢复证据继续遵守[留存合同](../../.agents/skills/oa-finance-preaudit/references/retention-contract.md)。

删除前持久记录来源标识、原本地位置、大小、内容指纹、计划时间和原因，删除后记录实际结果。中途退出保留计划与完成状态的区别。来源记录不保存含认证信息的临时下载地址。库存与逐文件账本仅供本机私有诊断，普通状态输出只给脱敏汇总。

本地已回收的材料明确标为已回收。当前读取遇到缺失材料时停止，不把原审核包当作仍有完整证据。需要重新取材时沿用现有授权与资源归属核验，不重开旧提交或自动恢复未知写入。

## 入口与迁移

统一入口是 `python3 -B -m scripts.project_space`。状态查询不修改材料正文、不搬迁或删除文件；会在库存锁内恢复上轮异常中断遗留的受管实验只读权限，未完成内容继续保护并计量。登记历史位置、创建实验目录、导入文件和回收分别是显式动作。具体参数使用该命令的 `--help`，不另建常驻清理服务或定时任务。

历史 `.scratch/`、生产附件和其他工作树不进行整目录搬迁或删除。迁移先核实际路径、任务、进程、打开文件和锁，区分源码、在用材料、可回收材料与未知项。只登记已核实的材料位置，未知项保持保护。若受保护材料已超过预算，报告超限并停止新增，不以删除保护项来获得通过状态。

新下载与派生产物通过受管写入入口。新实验文件通过受管实验和导入入口保存；代码、数据库、真实配置及回执不作为实验垃圾导入。实验结束后显式关闭，才允许按容量需要回收。

实验目录默认只读，文件也只读。使用 `import --name <名称> --file <来源文件> --filename <目标文件名>` 保存产物，使用 `finish --name <名称>` 结束实验。受管写入在库存锁内临时开放目标目录，完成或失败后重新封回只读。普通直接写入会被权限拒绝；这不构成任意 shell 命令的操作系统沙箱，同一用户仍可主动修改权限。后续预检会重新计入绕过入口产生的文件并阻断超限或未登记材料。

Office 转换使用 macOS 原生固定容量临时卷，转换输入、输出和私有配置共同受文件系统容量限制。后端不可用时明确失败，不回退到无容量限制的转换目录。卸载结果不明时保留镜像及配额，待核实挂载和子进程状态后处理。

上述写入规则只由已加载本版本的进程执行。旧版生产进程和未通过受管入口的外部程序不受其控制；本地提交不代表生产已启用容量门禁。发布与生产同步仍按[贡献指南](../../CONTRIBUTING.md#开发与生产隔离及发布)单独执行。

## 验证

沿用现有 quality workflow 和 pytest，不创建另一套检查平台。共享依赖验证两个工作树复用及源码来源隔离；材料验证并发配额、实际下载和派生写入、保护状态、越界拒绝以及删除位置账本。运行时库存检查负责本机真实占用，CI 只使用合成数据验证合同，不能代替现场迁移或生产验收。

pytest 原生临时目录只保留最近一轮失败用例，成功用例的临时文件随原生生命周期回收。此设置只管理 pytest 临时目录，不清理历史 `.scratch/`、其他聊天的工作树或生产材料。
