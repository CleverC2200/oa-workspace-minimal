# Bug 记录、复发与验收

GitHub Issue 是唯一问题状态源，Issue 编号也是 Bug ID。先从 [快速索引](../bugs/README.md) 找相关问题，再读取原票的范围、根因与验证证据；只读相关条目，不要求每次加载全部历史。新增条目可使用仓库 Bug 表单。

现场安全停止与原会话收尾优先；检索不可用时记录缺口，继续已授权的只读诊断和安全维护，不因建票或等待外部平台延后止损，也不放宽任何生产门禁。普通单据审核无需加载 Bug 索引或回归答案。

## 一次发生与一个问题

每次发生记录时间、代码/配置版本、受影响入口或阶段、脱敏运行身份、原会话及退出码、实际结果和证据引用。终态未取得填 `unknown`，恢复生产与根因修复分开记录。真实单号、requestId、账号、附件正文、内部地址及日志原文留在本地受控证据中，不进入 Issue 或索引。

同一 `run_id` 的重复观测追加到同一次发生；不同轮次是新事件，不把逐小时重复报错当成多次故障。缺少 run 身份时先按原会话/时间追溯，不能拿旧告警日期代替本轮。

按入口、阶段、触发条件和症状检索相似票。只有确认范围与根因一致才归并；只有症状相似或根因未知时标“相关、待确认”。新的独立根因另建票并交叉链接，不把所有 `controller_failed` 放成同一个已证实 Bug。

## 主票的必要内容

| 内容 | 记录要求 |
|---|---|
| 表现与影响 | 实际行为、预期行为、影响范围及模块/调用者 |
| 发生记录 | 按轮次去重的版本、会话/运行身份及脱敏证据 |
| 根因与责任位置 | 分开写已确认、推测、未知；明确改动应在哪个真实调用者生效 |
| 临时恢复 | 操作和回执、仍未解决的部分，不写成根因已消除 |
| 回归与反例 | 原错误的可执行复现、正常反例及受影响安全边界 |
| 修复与接线 | 分支/PR、受影响入口、依赖或旧路径收尾 |
| 验收与复发 | 工程验证、发布版本、适用的生产证据及复发记录 |

使用 [现有标签](triage-labels.md) 表示分类、优先级及需要的信息；`non-actionable` 只用于有明确依据的无需行动项。工程标签不授予生产操作权限，也不改变 OA 单据处理规则。

## 修复及关闭

1. 先取得能抓住原错误的复现信号，再改实现；复现不了时继续列证据缺口，不用模拟场景冒充历史根因。
2. 回归覆盖真实调用链，保留正常反例。例：长任务无输出但仍推进时不能判死；真正退出、未回收或未知写入仍必须阻断。Agent 行为要用工具事件或实际任务验证，指令字串检查只算静态审查。
3. 核对所有必要接线和适用版本；区分测试通过、代码合并、生产同步及真实运行。生产验收只使用正常授权轮次或另行明确授权的操作，不制造业务故障或重放历史未知写入。
4. 验收标准全部满足才关闭为 `completed`。根因还未确定、仅临时恢复或适用的生产证据未齐时保持打开。没有生产影响的局部问题明确记录生产验收“不适用”及理由，不机械要求额外生产运行。
5. 包含生产验收的 Bug 若尚未完成，代码 PR 使用 `Refs #<issue>`，按原发布门禁交付后补生产证据并关闭。大问题有多个可独立交付修复时才拆工程子票；完成子票可用 `Closes`，父票的整体验收仍保留。

不追溯性批量重开旧已关闭工程票。历史组件只证明其原范围；新发现的未解决问题登记为跟进或相关票，不把原范围已完成与整体问题根治混在一起。

## 已关闭后复发

先追加发生证据，核对实际加载的代码/配置版本、修改是否进入当前调用路径及原回归是否覆盖触发条件。同一范围与根因再次出现则重开原票，移除不再适用的无需行动标签并补回归；不同根因另建票，原票保留并相互关联。原票只做技术恢复入口时，不因另一个退出原因未知就认定其恢复实现失效。

## 经验与回归的归属

- 通用技术防错要点保留在相关规范/代码及测试中，Issue 引用责任位置和适用条件；索引只放检索词、Issue 与回归入口，不复制状态或事件清单。
- 人工确认的业务口径沿用 [反馈清单](../../.agents/skills/oa-finance-preaudit/references/confirmed-feedback.md)，脱敏输入/错误/预期沿用 [业务回归案例](../../.agents/skills/oa-finance-preaudit/references/regression-cases.json)。技术进程或调度事故不塞入业务答案集。
- 生产业务审核只读取现行规则和当前冻结材料，不把历史回归答案预先提供给审核 Agent。修复任务按需检索技术经验，不为记录清单自动安装 TeamAI、创建新调度或更换审核供应商。

维护索引时只更新导航和已有事实，状态以 Issue 为准。无需行动的记录按标签规范保留理由和原票链接，不从历史中删除。
