# 真实样例的财务质量核对

执行闭合、四项状态合法和业务事实正确是不同结果。原模型决定通过 FlowEngine preview 后，仍可能把费用对应关系未知写成全额可核销，或在 `uncertain` 项正文里宣称已入住、已结算。

沿用 `flow_evals.build_acceptance_report`，通过可选 `financial_reviews` 读取独立核对；无此参数的旧报告不代表已经增加财务语义验收。`build_financial_quality_report` 也可直接核对已经存档的 Worker 决定与最终 preview。调用不执行模型、OA 或状态恢复。

## 私有证据与核对流程

每个核对记录包含脱敏 `item_key`、清单、评估、可选财务确认及原回放开始时间。文件引用由绝对路径和 SHA-256 组成，路径、正文、姓名和审核细节留在私有目录，不进入返回的脱敏报告。

清单记录当前流程、场景、`source_kind`（真实存档 `real_archive` 或合成 `synthetic`），以及原资料、当前规则的文件引用。每个检查包含固定 `id` 与独立预期 `expected`。财务必须直接复核原资料、规则和预期，而不能把模型答案、历史“同意”或双方答案相同当作真值。清单不要求所有正常意见逐笔展开退款；确认退款影响未知或异常判断时不得抹掉该已知事实。

评估以 `method=independent_manual` 和私有 `reviewer_record` 标明独立核对来源，绑定清单指纹与被核对的原决定、最终 preview 文件。逐一填写检查的 `pass`、`fail` 或 `unverified` 和理由，不能自动按关键词评分，也不能只检查四项状态。这里允许工程人员准备事实核对草稿，以 `reviewer_role=engineering_draft` 标记，但它不是财务确认。真正的事后财务结果复核以 `reviewer_role=finance`、私有复核记录及带时区的 `reviewed_at` 记录，时间自然在回放后。事前预期签认不能替代事后结果复核。

财务确认是另一个私有记录，包含 `role=finance`、真实复核记录的引用、已批准清单指纹、带时区的确认时间。确认晚于既有回放开始时，不能把旧回放变成事前批准的试验。文件合同核验不认证人的身份；财务记录必须由负责人员真实提供，Agent 不得生成自签确认。

读取时校验全部文件指纹；清单或输出有改变，则旧评估失效。不要覆盖旧清单、评分或结果。改口径时创建新版本并说明旧口径为何过严，后续付费对照使用事前确认的版本。受试模型工作目录中不得出现预期、评估或旧模型答案。

返回的每个样例结论由人工逐项核对汇总：存在错误则 `fail`，还有未知核对则 `unverified`，全部正确则 `pass`。事前预期签认、事后财务复核和真实场景覆盖另外报告，不因草稿事实核对通过而认定真实对照准入。五类场景是普通支付、多支付/退款/确认超报、关系不明、合法共享支付、已确认异常与其他未知并存。合成样例可以测工程行为，不能补真实场景资格。

传给原验收入口时，评估的样例必须属于该次窗口及同一流程，所有闭合样例均需核对。未确认、缺场景或核对失败会令新增 `financial_quality_100` 门失败；旧资源覆盖、格式、用量及提交安全门继续保留。

## 当前草稿状态

已存档普通支付、多支付退款超报、原复杂关系样例可供财务复核。原复杂样例两侧错误全额通过；差旅对照中，不实已入住/已结算与正确保留未知应能通过同一核对入口区分，但该对照不能算业务招待优化收益。

合法共享支付、确认异常与另一行未知并存没有已确认的真实样例，本阶段保持未验证。财务签认尚未提供，不宣称 #363 完成或开启付费回放。历史“正常意见未展开退款即失败”的评分原档保留，新草稿记录校准原因，避免再次使用该理由单独判错。
