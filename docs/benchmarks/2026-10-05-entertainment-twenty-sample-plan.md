# 业务招待费二十单实际版本对照：事前准备

关联 [验收规格 #366](https://github.com/CleverC2200/oa-workspace-minimal/issues/366) 与 [准备票 #372](https://github.com/CleverC2200/oa-workspace-minimal/issues/372)。本文只记录本批选样及验证边界，实际正确性与性能结果须来自后续运行报告。

## 固定范围

本批从已捕获、带真实已办身份及同单审批记录的材料中，事前选定二十个不同业务招待审批单据。样本选择先于本批业务模型输出，按稳定审批单据身份去重；不同材料快照、处理尝试和修订回放不能增加单据数。

固定比较以下源码：

| 角色 | 提交 |
| --- | --- |
| 实际生产代码的只读回放 | `280fc829e7f30d13d399790e8c8adfc7a7d5612b` |
| 本地候选 | `6296bb81fe879e297f2a186f8b82b40f71b121f8` |

候选在本批保持不变，不修改业务规则、提示词、模型或推理配置。两侧使用同单同快照的原申报字段、原资源和原准备页，以及相同 `deepseek-v4-flash`、`high` 调用配置。生产工作树不执行回放、不切分支、不修改文件。

## 选样和预期

二十三条已有完整资料可用于抽样，选入二十条；两条按此次历史交叉依据完整度预先未选，一条在简单单笔层内预先未抽中。这些理由不否认真实已办身份，同额也不代表同一交易。包含此前五个回归代表，以及三十四页和二十四页的两张复杂单，不按模型结果或耗时删除慢单。

原材料、原附件、准备页及同单历史记录均在私有资料中以指纹绑定。原图由审核者直接观察，不用文件名或旧 AI 意见推定事实，不把历史“同意”单独当成真值。每单四项事实预期先核对后冻结，分别处理支付发生、费用对应、发票关联、预算策略及金额孰低；冻结预期不提供给模型。

原普通付款代表的一份较后快照已有财务审核金额，早期回放对应字段尚未解析。因此本批保留快照差异，不能直接复用那份旧执行记录为同材料有效配对。全部二十单计划各作一对新的生产代码与候选回放；旧四单候选结果、旧五单对照及失败记录仍保留，各有自己的版本和计数。

正常付款、优惠实付、退款超报、共享支付及复杂费用对应均有原资料代表。退款关系或费用对应未知，不等于已确认异常；两张复杂单的未知不能直接充作 `confirmed_exception_with_unknown`。若独立核图未发现真实异常与必要未知并存样本，该场景必须继续列为发布资格缺口，不能合成或由历史关键词代替。

## 现有入口与计数

仅沿既有 Worker → FlowEngine preview → 实际预审意见与存档报告入口验证。使用现有来源绑定、审核包准备、规则字节快照、预期冻结和配对准备能力；保留源版本角色和全部消费绑定。

这是实际版本整体对照：两侧真实规则不同。既有“仅初始输入交付变化”的纯效果准入会报告条件不匹配，因此不能用它宣称隔离了输入直供的独立收益，也不能通过改规则或关闭检查取得准入。规则差异明确记录，整体版本对照单独执行和报告。

二十个单据不等于二十次模型启动。本批计划二十对，至多四十个新 CLI 审核进程启动，每单每版本一次、每进程九百秒、无自动重试。此前耗尽的二十次修复额度不沿用。准备过程不启动付费模型；新批授权与实际启动记录由原执行负责人单独绑定。

技术失败、用量未知、过程未回收或候选事实核对失败时停止后续执行并保留证据。一次失败不能用同修订重跑碰通过；不能删除失败、将单侧结果算成完整配对或将未执行计划算成验证结果。

## 离线准备结果

已通过既有高层准备入口生成二十份来源绑定的配对计划，共四十侧审核包及八十项事前核对记录，准备阶段模型启动数为零。各配对的条件差异均只有真实版本规则；两侧模型调用配置、原资料和原页内容条件一致。

候选十七单使用完整初始输入；三条多明细单因正文超过直供上限，沿现有完整读取路径回退，原因均为 `text_limit`。两张重图单也在这三单内。未截断资料、改图或调阈值；最终性能必须保留并单列这三个真实回退，不只计算直供成功子集。

另有一单原历史支付、金额意见与独立原图事实不一致，预期冻结如实记录历史冲突；一单餐饮适用范围存在可辩护的多种判断，事前清单不强设唯一核销金额，须结合实际采用理由评分，未完成核验时不能计入合格数量。真实“已确认异常与必要未知并存”场景仍未确认。以上是资格缺口，不阻碍诊断执行计划准备，但不能把二十个选中单据称为二十个合格样本。

## 交付与验收边界

最终报告须分别展示不同真实单据数、同候选合格数、有效生产配对数、实际启动数及全部探索成本；给出事实正确率、平均耗时、P50/P95、各类 Token、工具调用和慢单贡献。性能只对真实有效配对计算，失败和未知用量另列并纳入总成本。

真实只读回放通过只说明当前范围内的质量和性能，不意味着已上线。二十个同版本合格样本、所需场景、工程审查及最终 CI 和发布验收分别判断；其他五类财务预审不在本批范围。

## 后续人工授权与实际执行修订

上文“候选事实核对失败时停止后续执行”是准备阶段的原规则。随后用户明确要求“测完20单”，授权这二十个不同真实单据各作生产代码与候选一次新回放，共四十次新 CLI 启动。原事前规则和冻结文件保留，不改写成从一开始就允许继续。

本轮发现业务事实错误时保留失败并完成剩余原计划。对于已由原负责人持有、进程正常退出且来源和原生用量可信的格式拒绝，记录为失败，保留原输出和成本，未伪造消费、未重跑；来源身份、执行归属、进程、用量或额度不可信仍停止。辅助归档与可信拒绝处理的修订没有改变应用、规则、提示、模型、图片参数或四十次上限。

实际二十单结果、失败与全部成本见[最终版本对照报告](2026-10-05-entertainment-twenty-version-comparison.md)。完成二十单测试不等于取得二十个同版本合格样本，父规格与资格不足的验收继续保持未完成。
