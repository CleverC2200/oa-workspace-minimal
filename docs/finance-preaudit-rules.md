# 六类财务预审现行审核规则

本文汇总当前生产代码中的六类财务预审规则，供财务、开发、测试和运维统一理解审核口径。本文是规则包的阅读版说明；发生差异时，以项目 Skill、冻结审核包及其唯一流程规则包为准。

本文不包含包装版面流程，也不把财务预审扩展为批准、退回或法规审核。AI 只形成预审意见；生产提交仍由受控宿主在身份、授权、冻结材料和唯一 Writer 门禁全部满足后执行。

## 1. 当前流程和规则版本

| 财务流程 | `workflow_key` | 当前规则版本 | 固定审核项数量 |
| --- | --- | --- | ---: |
| 差旅费报销 | `travel_expense` | `travel_expense:1` | 8 |
| 业务招待费 | `business_entertainment` | `business_entertainment:1` | 4 |
| 业务支持费 | `business_support_fee` | `business_support_fee:1` | 4 |
| 小额市场费 | `small_marketing_fee` | `small_marketing_fee:2` | 6 |
| TPM 小额市场费 | `tpm_small_marketing_fee` | `tpm_small_marketing_fee:4` | 4 |
| 通用费用报销 | `general_expense` | `general_expense:1` | 5 |

规则版本在审核包中冻结。审核者必须按审核包中的项目数量、名称、顺序和版本形成决定，不能在审核过程中改用其他流程规则。小额市场费发布前已经冻结的 V1 审核包仍按原五项闭合，不临时补第 6 项；新审核包使用 V2 六项。

## 2. 六类流程共用规则

### 2.1 结果状态

每个固定审核项只能使用以下一种状态：

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| `✅` / `pass` | 证据支持符合，或按已确认策略当前明确暂不校验 | 写明简明结论和可回查证据 |
| `❌` / `fail` | 完整可信证据明确显示不符合当前规则 | 写明具体不一致；只给意见，不写退回指令 |
| `⚠️` / `uncertain` | 证据缺失、冲突、归属不清、内容无法稳定读取或规则口径不足 | 写明缺少的事实或关系，交财务判断 |

所有项目均为 `✅` 时，整体结论为：

```text
AI审核结论：可提交 ✅
```

存在任一 `❌` 或 `⚠️` 时，整体结论为：

```text
AI审核结论：需人工判断 ⚠️
```

单项格式固定为：

```text
{✅/❌/⚠️} {编号}、{项目名}：{简明结论}
```

业务 `❌/⚠️` 是正常财务意见，不等于技术失败，不批准、不退回，也不能因为难以准确判断而阻断整轮。

### 2.2 证据关系

一条材料能够参与判断，必须同时证明：

1. 材料属于当前审批单据或具体费用明细；
2. 材料中的具体内容适用于当前审核项。

可以采用的稳定关系包括 OA 明细直接关联的附件、来源系统稳定资源 ID、发票云或公司主数据的权威关系，以及同时匹配同一明细至少两个关键字段的附件内容。以下信息不能单独建立证据关系：

- 文件名或上传顺序；
- 相似金额或相似日期；
- 页面相邻；
- 模型认为内容“看起来像”；
- 为凑申报金额而组合的候选凭证。

表单结构化字段和权威来源优先于附件推测。金额、主体、日期、地点、里程等高影响事实无法稳定读取时必须保持 `⚠️`，不能语义补猜。

### 2.3 附件和页面覆盖

当前单据的准备页必须完整覆盖。结构化内容足以回答审核项时可以不重复视觉读取；页面字节哈希完全一致时可以复用已经完成的页级观察；其余页面必须直接观察。

财务流程出现页面缺失、归属冲突、PDF 页数与准备页不一致或无法解释的未覆盖页面时，不采用不可信资源，受影响项目使用 `⚠️`。不能把“没有完成观察”写成“未发现问题”。

### 2.4 降级审核包与技术停止

当前 OA 登录、会话、执行身份和流程授权均可信，但材料下载、读取、归属或业务口径不足时，系统会丢弃不可信候选材料并生成降级审核包。审核者仍应逐项形成财务可读的 `⚠️` 意见，使单据正常闭合为 `needs_human`。

下列情况属于技术失败，当前执行停止且不生成财务意见：

- OA 登录失败、会话过期，或本地 RPA/CDP 会话不可用；
- 当前 OA 执行身份或流程授权无法可信确认；
- 单据身份不能唯一定位；
- 动作、状态、冻结材料、审核包、指纹或令牌不一致；
- 写入授权、提交目标或提交结果不可信；
- 系统无法安全持久化唯一处理尝试。

登录恢复后也不能自动重试历史 `needs_admin` 或 `write_state=unknown`，必须保留现场并人工对账。

### 2.5 金额展示

整体为“可提交”时，金额孰低核销之前的项目只说明证据状态和关联结果，不重复展示金额；“金额孰低核销”只展示一次最终核销合计。整体为“需人工判断”时，可以在相关项目展开说明异常所必需的金额，但仍应避免逐项重复同一事实。

## 3. 差旅费报销

现行规则包：[差旅费报销规则包](../.agents/skills/oa-finance-preaudit/references/flows/travel-expense.md)。

### 3.1 固定审核项

| 顺序 | 审核项 | 当前审核重点 |
| ---: | --- | --- |
| 1 | 报销周期 | 申报周期与全部可信实际行程日期是否一致 |
| 2 | 出差与住宿天数 | 出差天数、住宿夜数及负责区域内住宿上限 |
| 3 | 公共交通 | 票面或订单实际行程与考勤；没有时明确“未见公共交通” |
| 4 | 住宿与考勤 | 逐日比较实际住宿地点与考勤地点 |
| 5 | 跨区域带车 | 主表带车声明、考勤、通行费、油补、里程材料和负责区域 |
| 6 | 油补 | 起止里程原值、单位、差值与申报里程 |
| 7 | 个人垫付车票 | 线下个人垫付汽车票或火车票与费用明细 |
| 8 | 发票购买方 | 全部发票购买方与报销/开票公司 |

### 3.2 报销周期

- 先读取主表申报周期，再穷尽能够与当前单据或明细建立关系的实际行程日期。
- 交通采用实际乘车或起飞日期；住宿采用入住至离店日期；通行费采用实际通行日期；其他费用只采用语义明确的实际发生日期。
- 消费日期、下单日期、支付日期和开票日期不能单独替代实际行程日期。
- 全部实际行程日期位于申报周期内为 `✅`；任一可信实际行程日期明确超出周期为 `❌`；只能取得交易日期、实际日期缺失或可信来源冲突时为 `⚠️`。
- 商旅订单、票面、行程单或费用说明已经直接证明实际行程日期时，不能仅因缺少结构化“报销期间”而降为 `⚠️`。

### 3.3 酒店冲销、住宿天数和住宿地点

审核第 2、4 项前先处理酒店冲销：

- 优先按稳定订单号配对正负明细；没有订单号时，只有住宿人、入住离店区间、酒店或城市等关键字段能够唯一对应才可配对。
- 正负金额绝对值相等、净额为 0，并存在退款、退房或负数冲销标识时，才视为全额冲销。该住宿不计夜数，也不参与住宿地点与考勤比较。
- 部分退款、金额不等或配对关系不唯一时不能直接排除，相关项目使用 `⚠️`。
- 仅有酒店预订、没有入住或结算等实际住宿证据时，不能单独认定住宿地点与考勤不一致。

出差与住宿天数规则：

- 出差天数按考勤中“是否出差=是”的日期去重；住宿夜数按入住日至离店日逐晚去重。
- 销售代表负责区域内住宿上限为 10 天；其他销售人员为 20 天；职能人员不校验该上限。
- 只有职务类别、职务名称、负责区域和逐晚住宿地点均完整时，才能对上限给出明确 `✅/❌`；任一依据不足时为 `⚠️`。
- 酒店差标金额、`违/超标`、自付或审批金额不属于第 2 项判断依据。

住宿与考勤规则：

- 住宿地点优先采用绑定当前订单的酒店详情页完整地址或结构化“酒店地址”。
- 酒店名称中的商圈、门店或区域文字不是独立的行政区证据。
- 酒店地址归一到城市、区县后，再与同日考勤完整地址比较。
- 地点明确不一致为 `❌`；地址缺失或可信来源冲突为 `⚠️`，不能选择更符合预期的字段直接下结论。

### 3.4 公共交通和个人垫付车票

- 公共交通核对实际票面或订单行程与考勤。完整材料确认没有公共交通时，结论明确写“未见公共交通”。
- 个人垫付车票只审核线下个人垫付汽车票或火车票，并要求与对应费用明细建立稳定关系。完整材料确认没有此类明细时明确写“未见”。
- 两项都不能按文件名、相邻页面或相似金额补猜明细关系。

### 3.5 跨区域带车

- 主表“是否带车/是否自带车”中的“按次”等非否定值表示申请人声明带车。
- 主表声明带车，但全部考勤为“否”且没有通行费、油补或里程材料时，申报与证据冲突，使用 `⚠️`；不能直接判为不适用。
- 只有主表明确不带车，且其他来源均无带车线索时，才可按不适用给出 `✅`。
- 必须遍历全部带车日期和费用明细，从出差城市/县、行政区、打卡位置、收费站和里程定位中提取地点，不能只看前几行。
- 先根据常驻城市和完整行政地址形成常驻地集合，再剔除常驻地形成跨区域候选集合。
- 取得权威负责区域后，将跨区域候选与负责区域比较；缺少负责区域时为 `⚠️`，并区分已排除的常驻地、跨区域候选和无法确认行政归属的地点。

### 3.6 油补

- 每组里程必须记录照片中直接可见的起始读数、结束读数、单位和计算差值，并与申报里程比较。
- 不能采用旧 OCR/RPA 差值，不能把日期、时间、续航、短途里程或不同仪表区域中的数字拼入累计里程。
- 单一区间且一组起止读数能够唯一识别时，计算“结束里程－起始里程”；结果等于申报里程为 `✅`。
- 单一区间不额外要求每张照片都出现车牌或其他车辆标识。
- 多车辆、多组读数或按次申报必须逐组建立关系后求和，不能用全部照片最大值减最小值。
- 小数点、单位、末位数字、显示区域或起止配对无法稳定确认时为 `⚠️`；原值未确认前不能因异常差值判 `❌`。

### 3.7 发票购买方

优先采用发票权威来源，穷尽全部关联发票购买方，并与报销公司或开票公司比较。购买方读取失败、发票归属不清或公司字段冲突时使用 `⚠️`，不能只检查第一张发票。

## 4. 业务招待费

现行规则包：[业务招待费规则包](../.agents/skills/oa-finance-preaudit/references/flows/business-entertainment.md)。

### 4.1 固定审核项

1. 附件完整性/支付证据；
2. 发票关联；
3. 预算；
4. 金额孰低核销。

### 4.2 附件完整性、支付证据和发票关联

- 附件和发票必须与当前费用明细建立稳定关系；仅上传、但无法确认适用明细时不能作为符合证据。
- 有效支付证据不要求画面逐字出现“支付成功”。“支付成功”“交易成功”“对方已收款”等明确状态可以直接证明支付。
- 平台页面同时显示订单已完成、优惠后最终合计，并由订单号或 OA 资源关系绑定当前明细时，可以证明实际支付。
- 结算小票同时显示扫码支付、支付合计、结账时间和单号时，也可以证明实际支付。
- 只显示商品原价、待支付订单或无法确认结算结果的页面不能作为已支付证据；取消、关闭、失败、退款或待支付必须按真实状态处理。
- 发票关系或资源归属不清时使用 `⚠️`，不按文件名、顺序、相似金额或日期补猜。

### 4.3 预算

当前 OA 未提供可用预算数据，第 3 项固定使用 `✅`，并明确写：

```text
当前阶段按既定策略暂不校验，OA 暂未提供预算数据。
```

只有后续接入权威预算数据后，才能依据数据判断预算符合或不符合。

### 4.4 金额孰低核销

- 核销上限取能够绑定当前明细的实际支付金额、发票金额和申报金额三者最低值。
- 同一明细绑定多张支付凭证时，逐张读取交易状态和实际支出，排除重复页、失败交易和已确认退款后汇总；不能仅因凭证较多就停止在“无法汇总”。
- 优惠前原价与优惠后实付不一致时采用优惠后实付。
- 有稳定订单号、交易号或支付平台关联记录唯一绑定的退款时，实际支付按“已支付金额－已退款金额”计算。
- 退款关系不唯一、交易状态不明、归属不清或疑似重复时使用 `⚠️`。
- 申报金额高于已确认最低值时，第 4 项使用 `❌`。

同一支付事实覆盖多条拆分明细时，只有以下关系全部闭合，才能建立一个支付分组：

1. 每条明细由 OA 稳定绑定同一份页级精确重复凭证；
2. 业务上下文一致；
3. 拆分明细申报金额合计等于凭证实付金额；
4. 交易号或订单号可见时必须一致。

支付分组在金额汇总时只计一次，并如实说明分组明细和合计；不能虚构为每条明细各有一笔独立支付。必要关系不能闭合时使用 `⚠️`，不能因为金额恰好相加而强行分组。

## 5. 业务支持费

现行规则包：[业务支持费规则包](../.agents/skills/oa-finance-preaudit/references/flows/business-support-fee.md)。

### 5.1 固定审核项

1. 附件完整性；
2. 业务事项合规性；
3. 预算校验；
4. 金额孰低核销。

### 5.2 判定规则

- 完整可信材料明确显示完全没有附件时，第 1 项使用 `❌`。
- 附件完整可读，但没有出现必要事实或无法稳定关联当前明细时，第 1 项使用 `⚠️`。
- OA 声明或返回附件，但附件缺失、损坏、不可读或无法可信取得时，使用降级审核包和 `⚠️`；不能伪造证据，也不能改走旧入口。
- 业务事项合规性必须结合报销科目、科目解释和事项描述，不得只看其中一个字段。
- 当前 OA 未提供可用预算数据，第 3 项固定使用 `✅`，并明确写“当前阶段按既定策略暂不校验，OA 暂未提供预算数据”。

当前业务支持费规则包没有发布第 2 项的科目明细表，也没有为第 4 项发布独立的退款、共享凭证或金额去重公式。审核者只能依据当前冻结材料和上述已发布口径动态判断；标准不足、关系不清或金额无法准确收敛时使用 `⚠️`，不得复制业务招待费或通用费用规则补齐。

## 6. 小额市场费

现行规则包：[小额市场费规则包](../.agents/skills/oa-finance-preaudit/references/flows/small-marketing-fee.md)。

### 6.1 固定审核项

V2 固定六项：

1. 预算科目；
2. 附件完整性；
3. 费用承担主体；
4. SAP 客户编码匹配；
5. 金额孰低核销；
6. 支付公司一致。

发布前冻结的 `small_marketing_fee:1` 仍按原五项闭合；新单据使用 `small_marketing_fee:2`。V1 决定不能扩成 V2，V2 也不能降级为 V1。

### 6.2 预算科目和附件完整性

- 逐字读取每条明细的预算科目，不按相似词、文件名或附件顺序猜测。
- 预算科目等于“配送费-自提/租车费”时，继续按该科目已经发布的现有要求审核，不改变既有口径。
- 当前规则包只声明保留“配送费-自提/租车费”的既有口径，没有展开该科目的具体附件清单；审核时不得从通用费用复制一套规则，冻结材料也无法提供可信口径时使用 `⚠️` 交财务确认。
- 预算科目不等于“配送费-自提/租车费”时，每条明细必须同时具备可归属的支付截图和发票。
- 支付截图和发票均完整、可读且能稳定关联当前明细时，第 2 项使用 `✅`，结论必须明确写出“支付截图”和“发票”。
- 缺少任一类时使用 `❌` 并指出缺少类别；材料存在但归属、内容或读取完整性不可信时使用 `⚠️`。
- 预算科目无法可信读取时，第 1、2 项均使用 `⚠️`，说明科目和附件规则待财务确认；不能套用通用费用的科目规则表。

### 6.3 费用承担主体、SAP 和金额

- 第 3 项核对冻结材料能够证明的费用承担主体；当前规则包未发布额外的主体映射表，关系不足时使用 `⚠️`。
- SAP 主数据接口当前未接入，第 4 项必须使用 `⚠️`，不能写成已核验符合或“临时放过”。
- 第 5 项按当前冻结材料形成金额孰低意见；当前规则包未发布小额市场费专属的退款、共享凭证或去重公式，关系不清时使用 `⚠️`，不能借用其他流程的金额规则。

### 6.4 支付公司一致

逐字比较：

1. 表单“报销公司”；
2. 表单“支付公司”；
3. 全部关联发票的“购买方”。

三者必须完全一致，不做简称、括号、空格或公司类型归一化。全部一致时使用：

```text
✅ 6、支付公司一致：报销公司、支付公司、购买方三者一致，应选择***有限公司支付。
```

公司名称替换为当前单据逐字读取的实际公司。任一不一致时使用 `❌` 并简洁列出不同值；购买方读取失败、发票未关联、多张发票购买方冲突或任一公司字段无法可信读取时使用 `⚠️`。

## 7. TPM 小额市场费

现行规则包：[TPM 小额市场费规则包](../.agents/skills/oa-finance-preaudit/references/flows/tpm-small-marketing-fee.md)。该流程与普通小额市场费是两个独立流程；不得复用普通流程的 SAP 客户编码、费用承担主体或“配送费-自提/租车费”规则。

### 7.1 固定审核项

固定四项：附件完整性、发票关联与金额、金额孰低核销、支付公司一致。科目和凭证差异归入这四项。复用公共结果校验和完整签字意见输出，通过项也展示；不增加专用句式解析或问题清单分支。具体规则以现行规则包为准。AI 只给预审意见，不批准、不退回。

### 7.2 十类费用科目

| 费用科目 | 必需附件与专项要求 |
| --- | --- |
| `终端建设费-终端形象制作费` | 发票、广告公司盖章版制作清单、执行后现场定位照片 1 张；第一项核对数量、样式及制作单价；参考报价由宿主提供，不是申请人必传附件；清单印章与发票销售方一致 |
| `推广费用-物料费` | 发票、制作清单或购买明细、支付截图、制作完成定位照片；清单或明细与照片一致 |
| `终端建设费-其他` | 发票、支付截图 |
| `通路促销-订货会会务费` | 关联申请签报、发票、费用清单、签到表、支付凭据；每个申请不少于 4 张现场多角度全局定位照片 |
| `推广费用-产品赠品费` | 发票、支付截图 |
| `推广费用-试吃品费` | 发票、支付截图、执行试吃定位照片 |
| `促销员费用-管理费` | 发票、支付截图 |
| `促销员费用-激励费` | POS 复核数据表、激励政策（申请签报或签报截图）；POS 表只检查是否上传，不识别表内内容 |
| `促销员费用-统筹福利` | 关联申请签报、发票、支付截图 |
| `促销员费用-专项费用` | 发票、支付截图 |

### 7.3 制作单价与参考报价

V4 保持四项，制作单价判断归入第一项“附件完整性”。仅终端形象制作费逐项匹配编码、名称、规格和单位，按财务参考表 H 列含税指导价比较，不按发票税率换算，不包含安装运输。尺寸和组合构成可信时换算单位；名称编码冲突、规格不明或合并费用不可拆分时提示无法比价。高于、低于指导价都简短标注，不设容差；价格差异交财务核实，不直接判不合理，也不调整第三项核销金额。

使用以下只读导入命令把财务批准的 Excel 的“参考报价单”保存为本地配置。只提取参考表，不复制其他工作表和附件样例，不提交实际报价数据：

```bash
python3 -m apps.oa_finance_preaudit.tpm_price_reference /absolute/path/to/approved.xlsx
```

默认输出 `runtime/reference/tpm-price-reference.json`。如审核流程运行目录是 `/custom/runtime/finance_preaudit_flows`，导入时指定 `--runtime-root /custom/runtime`。宿主在准备适用单据时将目录、来源哈希及原表行号冻结进材料；后续表价更新只影响新材料。读取失败只影响第一项的单价核对，不误报申请人缺件，不技术阻断其余项目。发布到另一开发或生产克隆时需在对应运行目录单独导入批准的报价表；仅同步代码不安装本地报价数据。

V1/V2 六项和 V3 四项历史包保留回查；V4 不直接续审旧包，须按已有恢复权限重新准备，不在发布时自动恢复隔离或重试未知写入。

### 7.4 共用审核与本流程差异

按上述四项执行公共审核流程。科目表外按支付截图和发票检查；收款人与发票销售方一致且关系可信时免支付截图。仅纸质发票或收据检查邮寄及适用字段。终端形象制作费的盖章制作清单总额参与金额核验。公司一致性核对报销公司、支付公司和发票购买方。

发票关联到第一行不证明金额仅属于第一行，不能把整张发票与首行金额直接比较判错，也不能据金额相同推定全单覆盖。证据范围不清时说明待核实事实。完整条件见本流程规则包，不另设句式校验。

## 8. 通用费用报销

现行规则包：[通用费用报销规则包](../.agents/skills/oa-finance-preaudit/references/flows/general-expense.md)。

### 8.1 固定审核项

1. 附件完整性/支付证据；
2. 发票关联；
3. 预算；
4. 金额孰低核销；
5. 支付公司一致。

意见按整单汇总，相同事实不逐行重复；存在不一致时列出受影响明细。

### 8.2 各预算科目的附件要求

一般科目和未列入专属规则表的科目，统一使用兜底要求“发票+支付截图”。不能只因科目没有专属规则而输出 `⚠️`。

| 预算科目 | 必需附件或处理口径 |
| --- | --- |
| 一般科目、未列入专属规则表的科目 | 发票 + 支付截图 |
| `办公费-邮寄费` | 发票 + 运单明细；运单必须能看清起运地和目的地 |
| `办公费-驻地费` | 合同 + 发票 + 支付截图 |
| `车辆费用-车辆使用费` | 发票 + 支付截图 + 起止里程定位照片；意见展示可读起止里程 |
| `工会经费`、`员工关爱` | 相关签报 + 发票 + 支付截图；签报以表单“相关签报”实际关联流程为准 |
| `广告费-咨询策划费` | 发票 + 支付截图 + 消费清单；清单必须能看清具体消费产品 |
| `差旅费` | 发票 + 支付截图；提示“请走差旅费报销流程报销”，但不据此判定不符合 |
| `办公费-其他` | 当前流程已经不可选择，不设置独立审核逻辑 |

一个科目的全部必需附件都必须具备，缺少任一项即第 1 项使用 `❌`；材料存在但归属、内容或读取完整性不可信时使用 `⚠️`。

### 8.3 支付证据和特殊付款情形

- 支付截图必须显示可验证的实际支付金额和最终交易状态。
- 只有同一页面同时显示“实付 0 元”和确认收货后自动付款等未来付款承诺，才不是当前已支付证据。第 1 项必须明确写“实付 0 元，均为收到货后自动付款***元”；多笔时列出全部可读待付款金额。
- “先乘车后付款”不等于“先用后付”。页面明确显示“支付成功”和实际扣款金额时必须按已支付处理，并计入金额孰低核销，不得改写为实付 0 元或收到货后自动付款。
- 未来自动付款金额不能写成当前实付金额，也不进入可验证支付金额汇总。

已有支付截图、缺少有效截图、对公付款豁免及真实付款冲突的判断顺序统一见[六类共用规则](../.agents/skills/oa-finance-preaudit/references/payment-screenshot-exemption.md)。仅在缺少有效截图且未豁免时，按[通用费用第 1 项](../.agents/skills/oa-finance-preaudit/references/flows/general-expense.md#缺少有效支付截图时核对豁免及补充材料)核验人员关系及补充材料。

### 8.4 发票关联

- 每条明细的发票必须在 OA“关联发票”处建立关系。
- 只上传发票附件、没有在“关联发票”处关联时，第 2 项使用 `❌`。
- 整单存在未关联、错关联或无法稳定绑定的明细时，在意见中列出受影响明细。
- 资源归属或关联关系无法可信确认时使用 `⚠️`，不能按文件名、顺序、相似金额或日期补猜。

### 8.5 预算

当前阶段暂不校验部门年度预算，第 3 项固定使用：

```text
✅ 3、预算：当前阶段按既定策略暂不校验部门年度预算。
```

### 8.6 金额孰低核销

报销金额以表单明细“财务审核金额”整单合计为准。先按稳定关系去重并汇总有效发票金额和可验证实际支付金额：

- 有可验证支付截图：核销上限取报销金额、可验证支付金额、发票金额三者最低值；
- 没有可验证支付金额：核销上限取报销金额和发票金额两者最低值；
- 先用后付页面的未来自动付款金额不计入可验证支付金额，当前实付按 0 元处理；
- 同一支付事实或同一发票被多条明细稳定共享时只计一次；
- 归属、交易状态、退款、重复或共享关系无法闭合时使用 `⚠️`，不能为凑申报金额强行汇总。

申报金额高于已确认核销上限时，第 4 项使用 `❌`。意见输出整单最终核销金额；有差异时可以列出导致差异的明细，但不逐行重复三类金额。

### 8.7 支付公司一致

逐字比较报销公司、支付公司和全部关联发票购买方，不做任何名称归一化。全部一致时使用：

```text
✅ 5、支付公司一致：报销公司、支付公司、购买方三者一致，应选择***有限公司支付。
```

任一不一致时使用 `❌` 并列出不同值；购买方读取失败、发票未关联或多张发票购买方冲突时使用 `⚠️`。

## 9. 当前明确限制

- 财务预审只形成意见，不代替财务人员最终审核。
- 六个流程各自使用唯一规则包，不能横向复制科目表、金额公式或附件要求。
- 业务支持费尚未发布完整科目明细表和专属金额公式。
- 小额市场费 SAP 主数据接口尚未接入；“配送费-自提/租车费”的具体附件清单未在当前规则包展开；费用承担主体和金额项目尚未发布额外映射表或专属计算公式。
- 业务招待费、业务支持费当前没有权威预算数据，按已确认策略暂不校验。
- 通用费用当前暂不校验部门年度预算，但必须使用该流程规定的固定结论。
- 证据不足、规则模糊和业务关系不清使用 `⚠️`，不能为了让流程“通过”而补猜，也不能升级成技术阻断。
