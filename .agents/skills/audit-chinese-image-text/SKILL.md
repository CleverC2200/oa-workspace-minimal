# 中文图片文字交叉校对

把原始像素视为唯一原文。严格分离“图上实际写了什么”和“建议改成什么”；默认聚焦会影响产品识别、固定四项结论或使用安全的关键文字，不把装饰性文案的完整转写当成审批前置条件。未经人工确认，不输出已经修正的最终全文。

### OA 包装版面流程

- 先逐页目视分类为 `packaging_layout`、`non_packaging` 或 `uncertain`。承载消费者标签文字的包装袋、包装盒、标签、瓶贴，以及承载配料、过敏原、营养成分表或生产/经销单位名称或地址等固定项内容的运输外箱版面属于 `packaging_layout`；空白包材、模具、尺寸确认照片、与版面无关的截图，以及仅含品名、规格、储存条件、运输/堆码信息或生产日期填写位且不承载固定四项内容的储运外箱版面属于 `non_packaging`。不得仅因零售包装缺少固定四项就把它改判为 `non_packaging`；分类由视觉模型查看原图形成，采集脚本不得按文件名、扩展名或字段位置代替视觉判断。
- 可渲染 PDF 的每一页也是视觉候选，`review_role=packaging_image` 不等于已确认是本次申请产品的包装版面。混合 PDF 的证明函、原料标签或其他产品包装示例须逐页核对产品与版本关系；明确无关的页记为本次审核的 `non_packaging`，关系不明的页记为 `uncertain`，不得拿来补齐目标版本的四项。
- 上条零售包装缺项规则的例外：执行 [正面展示标签例外](../oa-finance-preaudit/references/flows/packaging-layout-approval.md#正面展示标签例外)。仅品牌、品名、规格、卖点和工艺且无实际固定项内容的清晰展示标签归为 `non_packaging`；孤立原料宣传徽章不是实际配料段。实际固定项或分类不确定页仍需审核。
- 同一单据只要存在一页 `packaging_layout` 就必须继续审核全部包装版面；`non_packaging` 页不进入固定四项。存在任一 `uncertain` 时不得整单跳过，应先用原图放大或方向辅助视图核验，仍不确定则进入人工判断。只有全部页面均明确为 `non_packaging` 时才跳过四项并输出唯一一句 `AI审核结论：非包装版面，跳过审核。`。
- 全部页面均已明确为 `non_packaging` 时，逐页分类覆盖就是该单据的完整视觉证据；不建立四项关键文字区域，不进入 G1-G3，也不因固定四项不存在而输出 `❌/⚠️`。存在包装页或分类不确定页时才继续下列 G0-G4 关键文字路径。
- 包装页按产品、口味、规格及正面/背面/局部图关系组成稳定 `package_version_id`。同一版本可以由多页共同闭合四项；一个原图同时承载多个版本时，对同一原图分别形成页面-版本观察，不拆造新页面。不得跨版本拼接证据；每个版本的配料、过敏原、营养成分表、地址四项必须全部覆盖。
- `workflow_key=packaging_layout_approval` 时，`review_role=packaging_image` 是必须逐页观察的包装图片；`review_role=excel_reference` 是存在时才使用的对照来源。
- 逐个下载 `review_role=packaging_image` 的原始附件，并以 `local_readonly_path` 或 `prepared.images[*].path` 的原始文件建立 G0；OA 页面缩略图、附件列表截图和聊天预览都不能替代原图。缺少任一已声明原图属于技术失败，不生成四项业务意见。
- 采集器只会按 Unicode 规范化后的完整附件名，删除“宣传附件”与“产品信息表”两个字段之间的同名副本；同一字段内的同名图片不得据此去重。审核时读取 `attachment_deduplication` 回查保留与删除关系，不能自行按附件顺序或相似画面继续去重。
- 没有 Excel 时仍完成原图下载、关键文字审核路径和四项签字意见，并明确未执行 Excel 对照；不得把缺少 Excel 视为失败，也不得用四项笼统 `⚠️` 代替像素观察。有 Excel 时只对能映射到关键文字的内容增加严格逐字符比较。
- **关键文字范围：**配料、过敏原、营养成分表、生产或经销单位名称与地址、许可证号，以及用于区分当前版本的产品名、口味/型号、规格净含量；清晰可见的储存条件、食用方法和警示语只在会影响使用或存在明显异常时纳入。
- 装饰性文字、营销口号、品牌故事、背景纹理文字、二维码周边推广语和重复出现且清晰一致的宣传文案默认不纳入逐字审核；用户明确指定、Excel 明确映射或主 Agent 发现明显异常时才升级为关键文字。
- OA 签字意见按配料信息、过敏原信息、营养成分表信息、地址信息四块内容汇总；只对原图实际存在或应存在的四块关键文字形成结论，不把四块拆成“图片文字、版面、Excel”三项。
- 关键文字检查错别字、漏字、多字、异常字符、关键数字/单位冲突和明显重复；不对普通营销文案做全面语病、文风或阅读习惯审查。Excel 存在时，把对应字符差异写入所属内容块，不另设 Excel 审核项。

## 不可违反的边界

- 禁止调用 OCR 引擎、OCR API、本地 OCR 模型或自动文字检测模型。转写必须由能直接查看原图或原始裁片的包装协调者或视觉复核 Agent 完成。
- 不按语义、品牌、上下文或相邻正确写法修正原文。图上出现 `Q`、`玉`、`亿` 等异常字符时，原文栏必须保留。
- 看不清时写 `〔疑似A/或B〕` 并标记低置信，不选择更通顺的候选。
- 同一关键文字的不同出现位置只有在内容不一致、像素低置信或承担不同审核作用时才分开记录；清晰一致的重复宣传文字不逐实例展开。
- 视觉子 Agent 的输出是独立证词。主 Agent 必须回看相关像素，且不能用多数投票静默删除少数意见。
- 默认由包装协调者完成一次关键文字目视校对。只有低置信、高影响数字或专名、Excel 差异或内部冲突才最多增加一次独立复核；用户明确要求全面逐字校对，或一次独立复核后关键冲突仍无法解释时，才升级为三路盲审。
- Excel 只有在用户明确指定为基准时才是权威文案源；否则只报告双向差异。
- 图片原文、Excel 原文、规范化比较值和建议修正必须分栏，不能相互覆盖。
- 每个异常位置单独列一行，禁止用“共两处”“等”或“同类问题”省略。
- 问题集只接收人工确认结论；历史案例只能提高复查敏感度，不能自动判错或改字。
- 用户在对话中明确指出“图上实际是 X”“X 应为 Y”“这是误报/漏报”或“该写法可接受”时，已经构成人工确认，不得要求用户重复确认。

## 闸门顺序

关键文字的当前闸门未闭合时不得形成该项确定结论；互不依赖的包装单据和关键文字区域可以并行准备。

| 闸门 | 闭合条件 |
|---|---|
| G0 原图基线 | 已记录原图尺寸、方向和关键文字区域清单 |
| G1 关键区域覆盖 | 协调者已确认关键区域可读；复杂或模糊版面所需的独立覆盖复核已完成 |
| G2 关键文字校对 | 协调者已完成主审；触发条件命中的区域已完成一次独立复核 |
| G3 隔离核验 | 提供 Excel 时关键文字对照完成；剩余冲突已保留或按需升级 |
| G4 汇总 | 固定四项、补充关键文字疑点和完整性计数一致 |

## G0：建立基线

1. 按原始分辨率查看已经下载的原图，记录路径、宽高、EXIF 方向和目视方向，不覆盖原图。
2. 先看完整画面，定位固定四项和其他关键文字；横置、倒置或竖排内容可另存旋转 90°、180° 或 270° 的辅助视图，旋转只能改变观察方向，不能替代原图或写回原附件。不得使用自动文字检测能力决定结论。
3. 建立关键文字区域清单，记录所属审核项、版面定位和相邻的关键数字、字母、单位或标点；同时记录被排除的非关键文字类别及排除理由，不逐字转写排除内容。
4. 主 Agent 读取[错误分类](references/error-taxonomy.md)和[问题集](references/problem-set.json)，但不得把任何历史 `observed → expected` 答案发送给盲审 Agent。
5. 每次任务开始先验证问题集：

```text
python3 .agents/skills/audit-chinese-image-text/scripts/problem_set.py validate
```

验证失败只停止学习写入，不妨碍继续只读校对。

### 提供 Excel 时

1. 先确认 Excel 是权威文案源还是待对比来源；用户未指定时按待对比来源处理。
2. 按 Spreadsheets Skill 只读打开，不修改、保存或导出原文件。
3. 记录工作簿、工作表、单元格、显示值、原始值和公式；保留合并单元格、换行及富文本的来源地址。
4. 建立 `区域 ID → 工作表!单元格` 候选映射；映射不唯一时列出全部候选并交人工。
5. 同时保留严格字符视图和仅供定位的辅助规范化视图。严格视图必须保留空格、换行、大小写、全半角和标点。

没有 Excel 时跳过 Excel 基线和后续 Excel 对照；仅在关键文字命中独立复核条件时增加视觉子 Agent。

## G1：关键区域覆盖

- 原图或清晰的自然文字面板可以直接作为观察输入；只有关键文字过小、方向复杂或相邻内容干扰阅读时才生成无损 PNG 裁片。
- 一个裁片可以保留同一自然面板内的标题、表格和相邻说明；允许为保证上下文保留必要重叠，重叠本身不是失败。字符不得贴边或被裁断。
- 裁片记录 `id`、`x`、`y`、`width`、`height`、所属关键文字类别和内容锚点。使用明确的左上角绝对像素接口；临时裁片不提交到仓库。
- 简单清晰版面由包装协调者直接完成覆盖自检，不启动独立覆盖审计。只有关键文字密集、方向混杂、存在极小字号或协调者无法确认覆盖时，才按[视觉子 Agent 提示](references/visual-agent-prompts.md)增加一个覆盖审计 Agent。
- 有效 `FAIL` 必须给出可执行的漏切或裁断位置。协调者最多执行一次定向重切；第二次仍不能闭合但原图与关键文字可读时，保留未闭合原因并把受影响的具体审核项标为 `⚠️`，继续审核其他关键区域，不得无限重切或无限等待。
- 只有原图本身缺失/不可读、已验证的绝对坐标无损裁切无法工作且关键文字无法从原图观察，或必需覆盖审计 Agent 的机器状态确实不可用且有界恢复失败时才技术阻断；分别使用 `packaging_g1_source_image_incomplete`、`packaging_g1_lossless_crop_unavailable`、`packaging_g1_coverage_auditor_unavailable`。

## G2：关键文字校对与按需复核

1. 包装协调者对每个关键区域做一次原像素目视校对，记录原文、低置信位置和疑点；不转写已排除的非关键文字。
2. 只有低置信、高影响数字或专名、Excel 差异或内部冲突才最多增加一次独立复核。复核 Agent 只接收当前区域、角色规则和输出格式，不接收预期答案或其他 Agent 输出。
3. 用户明确要求全面逐字校对，或一次独立复核后关键冲突仍无法解释时，才升级为三路盲审；升级范围只覆盖相关关键区域，不扩展到整张包装的装饰性文字。
4. 独立输出返回后立即冻结，后续核验只能追加字段，不能润色或覆盖原文。复核 Agent 不可用时，清晰区域保留协调者结论，受影响的低置信区域标为 `⚠️`，不把整单技术阻断。

## G3：隔离核验与关键字段比对

有独立复核输出时先冻结，再执行核验：

1. 需要历史特征复核时，使用脚本生成匿名特征交给独立复核 Agent：

```text
python3 .agents/skills/audit-chinese-image-text/scripts/problem_set.py features
```

匿名特征只能含 `category`、`feature_signature`、`detection_rules` 和 `outcome`，不得含 `observed`、`expected`、完整历史句子或当前疑似答案。

2. 提供 Excel 时，只把可唯一映射的关键文字候选单元格交给核验 Agent，追加严格逐字符差异；映射不唯一时列出候选并标 `⚠️`。
3. 对许可证、地址、关键规格、净含量、温度或日期等高影响字段，可使用数字与专名核验提示完成一次独立复核。
4. 协调者保留识别分歧、任一低置信、关键文字内部不一致、Excel 严格差异和映射歧义；不得用更通顺的写法覆盖像素观察。

## G4：输出与人工确认

完整读取并严格遵循[输出契约](references/output-contract.md)。先给结论，再给关键文字覆盖、主审、按需独立复核、Excel 对照、人工队列和完整性计数。只有受影响关键区域未闭合时才把对应项目标为 `⚠️`；不得因排除非关键文字而报告“部分完成”。

如果用户要求完整转写，按区域输出未经修正的全文，并明确：原文栏未做语义修复，建议尚未写回，未经人工确认不提供修正定稿。

人工为疑点选择 `确认错误`、`可接受写法` 或 `暂不确定` 后：

- `确认错误` 以 `confirmed-error` 写入问题集。
- `可接受写法` 以 `accepted-variant` 写入，作为降低误报的负例但不自动放行新实例。
- `暂不确定` 不写入问题集。

只保存通用、最小特征，不保存图片、Excel 路径、整段文案、公司名、证号或其他业务上下文。写入示例：

```text
python3 .agents/skills/audit-chinese-image-text/scripts/problem_set.py add --human-confirmed --outcome confirmed-error --category glyph-confusion --observed 销 --expected 铛 --feature-signature same-radical-different-component --detection-rule compare-every-term-occurrence --source-mode image-excel
```

重复特征不新增记录，只增加 `evidence_count`。

### 对话反馈即时沉淀

用户明确反馈图片文字识别或校对结论时，在同一轮完成以下动作：

1. 判断反馈属于图片转写/错别字能力，还是其他业务规则。只有前者写入本问题集；OA 财务审核口径等反馈写入对应业务 Skill，禁止混用。
2. 把反馈缩减为最小字符对或结构模式，移除图片路径、整句业务文案、组织名称、证号等上下文。
3. 明确纠正或明确漏报记为 `confirmed-error`；用户明确认可某种写法记为 `accepted-variant`；含“可能”“再看看”等不确定措辞时暂不写入。
4. 对纯对话纠正使用 `source-mode human-copy`；同时有当前图片证据时按实际情况使用 `image-only`、`image-excel` 或 `cross-instance`。
5. 调用 `problem_set.py add --human-confirmed ...`。相同特征由脚本增加 `evidence_count`，不要另建重复记录。
6. 再运行 `validate`，并在回复中简要说明记录了什么通用特征；写入失败时明确报告，不能假装已经学习。

新反馈只能用于下一次任务或当前任务已经冻结后的核验阶段，不得倒灌给仍在执行的独立复核 Agent。

## 判定锚点

- 图上是 `起酥油含量为Q`：原文保留 `Q`；建议栏可写“`Q` 疑似应为 `0`”。
- 标题是“电饼铛”、正文实际为“电饼销”：两个实例分别保留，并把 `销 → 铛` 作为人工建议，不能用标题覆盖正文。
