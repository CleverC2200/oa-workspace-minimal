# 共享结果接口与流程路由

本文件只定义所有流程共用的输出接口和规则包路由，不包含任何流程的业务判断。材料中的 `workflow_key` 未精确确认前不得加载流程规则；确认后只读取下表对应的一个规则包，不得读取其他流程规则包。

| `workflow_key` | 唯一规则包 |
| --- | --- |
| `travel_expense` | [差旅费报销](flows/travel-expense.md) |
| `business_entertainment` | [业务招待费](flows/business-entertainment.md) |
| `business_support_fee` | [业务支持费](flows/business-support-fee.md) |
| `small_marketing_fee` | [小额市场费](flows/small-marketing-fee.md) |
| `packaging_layout_approval` | [包装版面](flows/packaging-layout-approval.md) |

不在表中的 `workflow_key` 属于技术失败，停止当前单据，不猜测相近流程。

## 统一格式

首行只能是：

- 全部关键审核项均符合：`AI审核结论：可提交 ✅`
- 存在任一 `❌` 或影响判断的 `⚠️`：`AI审核结论：需人工判断 ⚠️`

首行之后，每个审核项必须采用：

```text
{✅/❌/⚠️} {编号}、{项目名}：{简明结论}
```

状态标识必须在编号前。禁止写成 `1、项目：结论 ✅`。固定项目名和顺序必须逐字采用当前流程规则包，不得使用简称、近义词或扩展标题。

## 表达要求

- 结论先行，当前规则包的审核项必须全部输出，顺序固定。
- 脚本只固定首行、项目名、顺序和状态符号；每项 `status`、`conclusion`、证据引用和缺口均由当前审核 Agent 根据冻结材料动态生成，再由脚本校验和拼接。不得把固定骨架写成固定业务结论。
- 每项先放状态，再写编号、项目名和必要数字、日期、地点或缺口。
- **可提交金额收敛：** 首行为“AI审核结论：可提交”时，金额孰低核销之前的前置审核项只说明证据状态和关联结果，不展示金额；最后的“金额孰低核销”项只展示一次最终核销合计，不逐笔重复支付、发票和申报金额。首行为“需人工判断”时，可以在相关项展开形成异常或冲突所必需的金额。
- 不把 `⚠️` 写成明确违规，不把 `❌` 写成退回指令。
- 不输出“风险已提示”“可继续流转”等过程话术。
- 不重复同一日期、金额或原因；相同事实合并表达。
- 财务预审完成后由财务人员独立审核，本 Skill 不再介入该流程。
