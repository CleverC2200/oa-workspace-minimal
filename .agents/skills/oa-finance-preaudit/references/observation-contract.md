# 证据阅读规则

## 两层关系

每条可用证据必须回答两个问题：

1. 为什么该资源属于当前审批单据或具体费用明细？
2. 资源中的哪一处内容支持当前审核项？

第一层关系不成立时，资源不得参与判断；第一层成立但第二层不成立时，只能证明“附件已读取”，不能证明审核项符合。

## 可接受的关系

- OA 或商旅来源返回的稳定资源 ID，并明确绑定当前 requestId；
- OA 明细行直接记录的附件 ID；
- 附件内容同时匹配同一明细的至少两个关键字段，例如金额与日期、路线与乘车人；
- 发票云、官方主数据或表单结构化字段返回的稳定业务关系。

仅有文件名、上传顺序、相似金额、相似日期或模型觉得“像”均不成立。

## 记录方式

Codex 的工作笔记至少保留：

- 来源资源 ID 或表单字段路径；
- 页码、图片区域、表格行或文本锚点；
- 直接看到的原值；
- 它支持的审核项；
- 关系不清时的具体缺口。

不要求为了记录而新增 evidence graph、领域类或持久化表。当前 preview 可以在本次任务上下文中完成；不得在项目中落旁路审计 JSON。

## 事实优先级

1. 表单结构化字段和官方权威来源；
2. 可确定性解析并定位的附件内容；
3. Codex 对原始页面的直接视觉观察；
4. 无法确认的候选内容，标记为未知。

不得从里程照片的拍摄时间推断费用日期，不得从酒店名猜行政区，不得从报销金额反推付款金额或行程。

## 页面覆盖

先在当前任务上下文建立页面覆盖表，再开始看图。逐页按以下顺序分类：

1. `prepared.structured_contents` 的页码和文本已经包含当前审核所需全部原值时，标记“结构化内容已足够”，不进入视觉队列；
2. `prepared.images[*].content_sha256` 与已观察页面相同时，标记“页级精确重复”，复用观察并分别映射全部资源归属；
3. 其余页面按 `owner_detail_id`、`resource_id`、页码和当前审核项直接观察。

同一单据由当前审核调用完整读取，不在单据内部建立角色、消息交接或第二套页面队列。涉及版面对应、印章、手写、照片或结构化文字未覆盖区域时仍须读取页面。`source_content_sha256` 只能说明源文件字节相同，不能代替页级覆盖。

## 全页覆盖门禁

形成预审意见前，逐项核对 `prepared.images`：每个页面路径必须对应以下一种记录：

1. 当前 Codex 的直接观察；
2. 同一页面的确定性文本已足以回答当前审核项，并记录跳过视觉读取的原因；
3. 与已观察页面的 `content_sha256` 完全一致，并记录被复用观察的页面标识。

覆盖记录必须逐页映射回全部 `prepared.images`，包括结构化内容已足够、页级精确重复和进入视觉队列的页面。四类财务流程发现页面缺失、资源身份冲突、归属不可信、PDF 页数与渲染数量不一致或无法解释的未覆盖页面时，不采用对应资源，并把受影响审核项写成 `⚠️` 交财务判断；不得把未执行观察写成“未发现问题”。包装流程缺少可观察页面时按技术失败停止。

金额、主体、日期、里程等高影响事实无法稳定读取时保持 `⚠️` 并写明缺口，不通过投票或语义猜测补齐。
