# 证据阅读规则

## 两层关系

每条可用证据必须回答两个问题：

1. 为什么该资源属于当前审批单据或具体费用明细？
2. 资源中的哪一处内容支持当前审核项？

第一层关系不成立时，资源不得参与判断；第一层成立但第二层不成立时，只能证明“附件已读取”，不能证明审核项符合。

## 可接受的关系

- OA 或商旅来源返回的稳定资源 ID，并明确绑定当前 requestId；
- OA 明细行直接记录的附件 ID；
- 附件内容同时匹配同一明细的至少两个关键字段，例如金额与日期、路线与乘车人；
- 发票云、官方主数据或表单结构化字段返回的稳定业务关系。

仅有文件名、上传顺序、相似金额、相似日期或模型觉得“像”均不成立。

## 记录方式

Codex 的工作笔记至少保留：

- 来源资源 ID 或表单字段路径；
- 页码、图片区域、表格行或文本锚点；
- 直接看到的原值；
- 它支持的审核项；
- 关系不清时的具体缺口。

不要求为了记录而新增 evidence graph、领域类或持久化表。当前 preview 可以在本次任务上下文中完成；不得在项目中落旁路审计 JSON。

## 事实优先级

1. 表单结构化字段和官方权威来源；
2. 可确定性解析并定位的附件内容；
3. Codex 对原始页面的直接视觉观察；
4. 无法确认的候选内容，标记为未知。

不得从里程照片的拍摄时间推断费用日期，不得从酒店名猜行政区，不得从报销金额反推付款金额或行程。

## 视觉队列

先在当前任务上下文建立页面覆盖表，再开始看图。逐页按以下顺序分类：

1. `prepared.structured_contents` 的页码和文本已经包含当前审核所需全部原值时，标记“结构化内容已足够”，不进入视觉队列；
2. `prepared.images[*].content_sha256` 与已观察页面相同时，标记“页级精确重复”，复用观察并分别映射全部资源归属；
3. 其余页面进入视觉队列，按 `owner_detail_id`、`resource_id`、页码和窄问题组成视觉工作单元。

一个视觉工作单元通常包含同一明细下不超过 4 个相互关联的页面；同一 PDF 连续页或必须共同判断的起止、支付退款、订单付款材料保持在同一单元。并发数量按视觉工作单元数计算，不按附件总数或渲染总页数计算：

- 1–3 个视觉工作单元：当前 Codex 直接读取；
- 4–12 个视觉工作单元：使用 2 个原生观察子 agent；
- 超过 12 个视觉工作单元：最多使用 3 个原生观察子 agent，主 agent 只负责资源归属、跨单元关系和最终判断。

## 视觉观察子 agent

当前 Codex 可以直接阅读 `prepared.images`。子 agent 不可用时由当前 Codex 继续，不得改用嵌套 `codex exec`、模型 API 或其他兼容 worker。

分组必须先按 `owner_detail_id`、`resource_id` 和页码组织；同一费用明细的相关资源不得拆给互相看不到上下文的观察者，同一 PDF 原则上保持连续页完整分组。不能为了均分数量把资源归属打散。

涉及版面对应、印章、手写、照片或结构化文字未覆盖区域时仍须读取页面。`source_content_sha256` 只能说明源文件字节相同，不能代替页级覆盖。

给子 agent 的输入只包含同一次冻结材料中的：

- `request_id`、`workflow_key`；
- `resource_id`、`owner_detail_id` 和来源系统；
- 需要读取的全部页面路径及页码；
- 与窄问题直接相关的申报字段原值。

不得提供已有审核结论、旧 RPA 意见、财务反馈、预期答案或另一视觉观察者的输出。每个视觉工作单元先按高细节读取；只有金额、日期、主体、交易号、里程或末位字符仍不清楚时，才把该页升级为原始分辨率，不因一处模糊重读整组。

子 agent 对每页返回以下最小观察结构；`visible_fields` 只列画面中直接可见且当前窄问题需要的字段：

- `resource_id`；
- `owner_detail_id`；
- `page` 或图片标识；
- `visible_fields`：原值、位置及必要的交易状态、交易号、订单号、金额、日期、主体或里程单位；
- `uncertainties`：无法辨认、被遮挡、未出现或来源冲突的字段。

缺少资源定位的观察不得采用。观察结构已经包含当前相关字段且没有模糊项时，主 agent 不得重复打开同一页面；直接复用观察完成其他适用审核项。只有新问题需要未记录字段时才重新读取。当前 Codex 必须重新核对资源归属和审核适用性，再形成 `✅/❌/⚠️`；不得把子 agent 摘要直接当成独立来源事实。

## 全页覆盖门禁

形成预审意见前，逐项核对 `prepared.images`：每个页面路径必须对应以下一种记录：

1. 当前 Codex 的直接观察；
2. 原生子 agent 返回的带 `resource_id` 和页码的观察；
3. 同一页面的确定性文本已足以回答当前审核项，并记录跳过视觉读取的原因；
4. 与已观察页面的 `content_sha256` 完全一致，并记录被复用观察的页面标识。

覆盖记录必须逐页映射回全部 `prepared.images`，包括结构化内容已足够、页级精确重复和进入视觉队列的页面。发现页面缺失、资源身份冲突、归属不可信、PDF 页数与渲染数量不一致或无法解释的未覆盖页面时，按技术失败停止；不得把未执行观察写成“未发现问题”。

## 隔离复核

只有金额、主体、日期、里程等高影响事实因图像模糊而无法稳定读取时，才增加一次看不到首轮答案的独立子 agent 复核。两次结果不一致时保留 `⚠️`，不要投票或选更顺眼的值。
