# 已确认反馈清单

本文件只记录用户在人工测试中明确确认的通用口径、采纳状态和规则落点。具体输入事实、旧错误输出和正确输出记录在 `regression-cases.json`；不得把案例详情重复写入本文件。两份记录均不得记录流程编号、requestId、人员、公司、附件正文或截图路径。

结果契约是执行时的唯一规则来源。本清单用于追溯反馈是否已经落地，不能绕过盲测，也不能作为当前样本的答案提示给观察子 Agent。

状态含义：

- `已采纳`：已写入结果契约或 Skill 边界，并有聚焦验证；
- `待样本`：反馈已记录，但证据不足以形成稳定规则；
- `暂缓`：口径已确认，但当前阶段明确不实现自动能力。

## 新反馈记录规则

F-029（六类财务，已采纳）：CPU 资源紧张时降低审核并发并保留队列，不能因资源等待跳过 AI 或转财务人工。严重内存不足等安全故障仍停止。规则落点：`flow-engine-contract.md` 资源等待段；聚焦验证：`test_resource_pressure.py`；错误案例 RC-029。

F-028（六类财务，已采纳并按生产反馈修正）：当前受控 AI 超时在身份、冻结、授权和未写入状态可信且进程回收确认时，以特别说明转财务人工审核，不等待 AI 重试。结构校验失败不得写入 OA：有效对象第一次无效时重试一次，第二次隔离当前单据；原始输出不可解析时直接隔离当前单据，两者都继续后续 FIFO。保留安全门禁，包装和历史隔离不自动使用超时交接分支。规则落点：`flow-engine-contract.md` 的“审核未完成的人工交接”；回归见 `test_manual_handoff.py` 和 RC-028。

1. 用户明确说明“应按什么判断”“这里误报/漏报”或指出权威字段时，直接视为人工确认，不再重复询问。
2. 同一反馈重复出现时更新原条目的验证证据，不新增含义相同的条目。
3. 只有可复现、可泛化且不依赖单一流程隐私上下文的纠正才进入结果契约。
