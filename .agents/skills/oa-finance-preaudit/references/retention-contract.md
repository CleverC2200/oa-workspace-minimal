# 30 天留存合同

运行证据只为追溯、时效和 Token 优化服务，不建立长期业务索引。结构化日志、脱敏事件、单据指标、CLI 调用回执和冻结状态保留 30 天；不含 item_key 的日/流程聚合保留 180 天。年龄等于边界时仍保留，严格超过边界才进入删除计划。日界固定为 Asia/Shanghai。

可回收的本地附件副本及其派生产物按[项目空间管理](../../../../docs/agents/project-space.md)执行容量优先回收，不保证原件在本机保存满 30 天。正在处理、未闭合、写入未知及恢复所需材料继续保护，历史冻结路径不改写；容量不足时拒绝新增。原结构化状态、提交回执和脱敏审计仍按本合同保留。

## 任务生命周期

- 每个 `workflow_key` 只保留创建时间最新的一轮可见任务；之前已闭合且仍在 30 天内的任务归档。
- 严格超过 30 天的非最新已闭合任务删除；年龄使用创建时间和最后有效事件时间中的较晚者。
- 正在处理、未闭合或 `write_state=unknown` 的任务与材料始终保留，不受年龄影响。
- 归档和删除只接收任务标识，不读取或复制任务正文。

## 文件清理

清理固定执行 `列举 → 计算计划 → 全量校验范围 → 删除`。调用方必须显式提供一个已由 `.oa-retention-root` 标记的运行根；根目录符号链接、未标记根、绝对目标、`..` 越界和解析后逃逸都必须在任何删除前失败。

`python3 -m apps.oa_finance_preaudit.cli status --root <path>` 从 FlowEngine 的 attempt 状态、终态质量回执和脱敏事件生成版本化 JSON，只含流程、哈希、计数、年龄、三维状态、失败码、阶段 P50/P95、Token 完整性及 180 天日聚合。日聚合同时保存业务结果、技术失败、写入 unknown、质量覆盖和提交安全计数，不保存单据哈希。不得读取或输出材料、意见、requestId、人员、公司、附件名或绝对路径。status 是运维入口，不加入审核 Agent 的正常上下文。

`python3 -m apps.oa_finance_preaudit.cli prune --root <path>` 调用 `runtime_maintenance`，在同一维护锁和源事件锁内计算日聚合、校验完整预期计划及全部路径，随后以不跟随符号链接的原子写入保存 `.metrics/daily/`，最后才执行归档和删除。计划不得来自未来且生成后 5 分钟失效。30 天内的旧已闭合 attempt 移入根内 `.archive/`；严格超期的旧 attempt 删除；最新、未闭合、状态无效或 `write_state=unknown` 的恢复证据保留。严格超过 180 天的合法日聚合由同一计划删除。重复执行时，已不存在的目标计为 `missing`，不得扩展目标范围或报为成功删除。

附件下载索引属于可重建缓存，不属于业务 attempt。滚动生产控制器在每次启动及每个滚动轮次前只删除严格超过 30 天或时间戳无效的缓存行；缓存维护失败只返回脱敏 `status=failed`，不得阻断当前生产轮次。人工全量清理固定使用 `python3 -m apps.oa_finance_preaudit.cli clean --all-cache`，只清空当前配置的附件缓存数据库；控制器、全局 Writer 或任一请求 Writer 活动时必须拒绝。重复执行返回 `deleted_entries=0`，不得删除业务 attempt、提交边界、终态回执、unknown 对账证据或审计日聚合。

滚动控制器在唯一控制器锁内原子记录脱敏 run manifest；只读 `status` 同时返回 handoff 状态。manifest 只保留代码提交、配置指纹、进程实例链、fresh-process 重启证明、锁拥有者一致性、Writer 启动前空闲、子进程回收和终态健康，不包含原始配置、业务身份或附件。上次 manifest 仍为 `running`、无效、属于当前同一进程实例或明确未回收子进程时，新控制器必须失败关闭；普通已终态技术失败在子进程确认回收且由新进程接管后仍可廉价重试。

`apps.oa_finance_preaudit.retention` 保留纯计划器、受限文件执行器和任务回调接口，不内置真实任务系统凭据。

## 脱敏回执

每次执行只记录开始时间、完成时间、归档数、删除数、已缺失数、失败数和总体状态；不得包含任务标识、requestId、人员、公司、附件名、正文、意见或绝对路径。单个动作失败只进入失败计数，其他已校验动作可继续。

项目只提交清理能力和测试，不自动标记现有生产目录，也不创建、启用或恢复生产清理任务。启用前必须由 Admin 确认准确运行根和真实任务系统的测试任务回执。
