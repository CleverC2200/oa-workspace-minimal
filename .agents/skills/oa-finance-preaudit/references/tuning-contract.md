# 基于证据的并发调参合同

并发调参只生成建议，不直接修改 `config/flow-runners.json`，也不创建、更新或启用生产 automation。五个 workflow_key 独立计算；一个流程的积压、错误或建议不得改变其他流程的值。

## 最小证据门

每个流程至少需要 20 张已闭合单据，并为每张提供：闭合时间、总耗时、审核耗时、审核等待、提交等待、平台精确 Token、错误标记和重复提交标记。少于 20 张时，P50/P95、等待占比和 Token 固定输出 `unknown`，保持当前值，不给伪精确结论。

以下任一条件命中也保持当前值：

- 任一 Token usage 为 `unknown`；
- 离线 golden replay 的准确率或格式合规率低于 100%，或仍有差异；
- 重复提交率大于 0；
- 错误率大于 2%；
- P95 总时效和等待占比没有形成明确压力信号。

## 建议与上限

有效窗口按流程计算 P50/P95 总时效、P50/P95 审核时效、总等待占比、审核/提交等待占比、Token/单、错误率和重复提交率。只有 P95 总时效达到 900 秒且对应等待占比达到 20%，才建议把相应并发增加 1。

Reviewer 和 Submitter 的单流程上限均为 3，并且建议值必须小于调用方提供的共享实际槽位，至少留出一个共享槽位；无法留槽时不扩容。积压量本身不是扩容依据。

每条建议必须包含样本窗口、当前值、建议值、指标、假设、预期效果和回退值。回退条件固定包括：质量准确率或格式低于 100%、出现重复提交、错误率比基线增加超过 2 个百分点，或 P95 总时效恶化超过 20%。

建议只可进入小流量受控窗口；窗口结束后使用同口径做前后对比。任何安全或质量回退条件命中，先恢复记录中的旧值，再调查原因，不通过降低证据完整性或提交门禁换取吞吐。
