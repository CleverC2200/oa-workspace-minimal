# 包装版面规则包

本规则包仅适用于 `workflow_key=packaging_layout_approval`。先执行[共享结果接口](../result-contract.md)，不得读取其他流程规则包。

完整读取并执行 [`$audit-chinese-image-text`](../../../audit-chinese-image-text/SKILL.md) 及其按闸门要求引用的 reference。脚本只提供来源字段、同名去重记录、图片页面和 Excel 结构化内容，不生成校对结论。

## 固定审核项

固定四项，顺序不可改变：

1. 配料信息；
2. 过敏原信息；
3. 营养成分表信息；
4. 地址信息。

## 逐页视觉分流与版本关系

逐页直接查看原图并分类：承载拟审批印刷文字的包装袋、包装盒、标签、瓶贴、运输外箱版面使用 `packaging_layout`；空白包材、模具、尺寸确认照片及与版面无关的截图使用 `non_packaging`；原图不足以可靠分类时使用 `uncertain`。分类只由视觉模型形成，脚本不得根据文件名、扩展名、上传字段或自动文字检测生成分类。

混合上传时，只要存在一页 `packaging_layout` 就必须审核全部包装页，`non_packaging` 页不进入固定四项。存在 `uncertain` 时不得整单跳过；原图放大或方向辅助视图后仍不能闭合的分类进入人工判断。只有全部页面均明确为 `non_packaging` 时才跳过四项，OA 签字意见只输出 `AI审核结论：非包装版面，跳过审核。`，不追加四项、说明或 Excel 对照。

包装页按产品、口味、规格及正面、背面、局部图关系组成稳定版本。同一版本可以由多页共同覆盖四项；每个版本必须分别闭合配料、过敏原、营养成分表和地址四项，不得跨版本拼接证据。

## 审核范围

此流程的主体是包装图片关键文字校对，不是法规合规审查。默认聚焦配料、过敏原、营养成分表、单位名称与地址、许可证号，以及区分版本所需的产品名、口味/型号、规格净含量；忠实保留图片原文，不得按语义自动改写。装饰性文字、营销口号、品牌故事、背景纹理文字和清晰一致的重复宣传文案默认不纳入全面逐字、语病或文风检查。

每一版包装图片都必须输出上述四项；多版包装合并为四项签字意见时，逐版覆盖并在异常项中给出可回查的版本或区域定位。确认某块内容缺失时按漏项使用 `❌`；图片页数、裁切或版面关系不足以确认是否缺失时使用 `⚠️`。四块均无异常时分别说明未见漏项、错别字、重复或表达异常，不得用一条笼统的“包装图片文字符合”代替四项。

四项分别检查对应关键文字中的错别字、漏字、多字、异常字符、关键数字/单位冲突、重复印刷和内部写法冲突。过敏原段落等可见内容只有在重复关系和位置均可确认时，才因非预期重复使用 `❌`；合理版面中的正常重复不能仅凭出现次数判错。营养成分表同时核对项目名、数据、单位和符号。地址信息同时核对地址、生产者文字和生产许可证号等数字专名；这些高影响字段看不清时使用 `⚠️`。

清晰可见的储存条件、食用方法和警示语，只有在会影响使用、存在明显异常、用户明确指定或 Excel 明确映射时才纳入关键文字。发现异常时保持四项项目名和顺序不变，把全部非四项关键异常合并到唯一一行非编号的 `补充校对`，用分号逐项写明版本或区域定位及实际疑点；不得输出多行 `补充校对`，不得用“等”省略已确认异常，也不得把问题硬归入固定四项。普通装饰或营销文字不因未逐字校对而生成补充校对。

许可证号、地址、配料、过敏原和营养成分只作为图片文字或 Excel 对照内容：可以报告字符不一致并将证号等专名列为高影响疑点，但不判断许可证真伪、法规有效性、配方合规性或标签是否合法。用户提供的具体异常是已确认案例，不得把具体字符或结论变成其他包装的预期答案。

## Excel 对照

材料中存在 `review_role=excel_reference` 的 Excel 时，只对能映射到关键文字的内容执行严格逐字符对照，保留替换、缺失、新增、顺序、重复、空格、换行、大小写、全半角、标点及数字差异。映射唯一且与 Excel 不一致时使用 `❌`；映射不唯一或字符看不清时使用 `⚠️`。

Excel 文件通常同时承载四块信息：四项内只写各自图片结论及实际存在的字符差异或映射疑点，Excel 来源状态只在四项之后统一说明一次。没有 Excel 时仍完整审核四块关键文字，并在末尾追加非编号行 `Excel 对照：本次未提供 Excel，未执行 Excel 对照。`；不得在四项中重复该句，不得把缺少可选 Excel 当成技术失败或业务不符合，不得仅因未提供 Excel 将四项统一标为 `⚠️`，也不得另设第五个审核项。只有对应关键区域经主审和实际触发的按需复核后仍存在真实像素分歧或证据缺口时，才把受影响的具体项目标为 `⚠️`。

有 Excel 且四块对照完成时，末尾使用 `Excel 对照：上述四项已与同一 Excel 逐字符对照；具体差异已写入对应项目。`。Excel 对照行不编号、不带状态，不参与四项状态计数；若还存在 `补充校对`，先写补充校对，Excel 对照行保持在意见末尾。

## 观察与复核

- 当前审核 Agent 是该单据的独立包装审核协调者。默认直接完成关键文字覆盖自检和主审；只有低置信、高影响数字或专名、Excel 差异或内部冲突才增加一次独立复核，只有增强模式才启动 A/B/C 三路盲审。
- 每个 `packaging_image` 原图下载、关键文字区域清单建立且关键文字审核路径已闭合后，才能生成四项签字意见。保留原图尺寸、方向、关键区域清单、主审状态及实际触发的复核状态；不要求 A/B/C 三路齐全。
- 包装 G1 返回有效 `FAIL` 时，只按可执行问题清单执行一次定向重切。第二次仍不能闭合但原图关键文字可读时，记录缺口并把受影响的具体审核项标为 `⚠️`，继续处理其他区域，不得无限重切或无限等待。
- 只有三类不可恢复条件可以技术阻断：原图本身缺失或边界裁断且关键文字不可读使用 `packaging_g1_source_image_incomplete`；已验证的绝对坐标无损裁切无法工作且原图也无法观察关键文字使用 `packaging_g1_lossless_crop_unavailable`；必需覆盖审计 Agent 机器状态确实不可用且有界恢复失败使用 `packaging_g1_coverage_auditor_unavailable`。泛化的 `packaging_g1_coverage_failed` 不再允许封存新 attempt。
- 只有复杂或模糊版面才启动覆盖审计 Agent；简单清晰版面由协调者直接覆盖自检。必需 Agent 仍为 active/running 且有任务进展时继续有界等待，不得并发启动替代；任务系统明确失败或停止后才按同一 attempt 恢复。可选独立复核不可用时把受影响的低置信关键区域标为 `⚠️`，不得把整单技术阻断。
