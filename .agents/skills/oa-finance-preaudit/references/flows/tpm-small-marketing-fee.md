# TPM 小额市场费规则包

适用于 `workflow_key=tpm_small_marketing_fee`，当前版本 `tpm_small_marketing_fee:3`。复用[共享结果接口](../result-contract.md)和公共取数、证据准备、结果校验及意见输出；差异仅在本流程的科目、附件要求和以下四项规则。不得套用普通小额市场费的 SAP 客户编码或费用承担主体要求。

AI 只形成预审意见，不批准、不退回。判断来自当前流程可回查的字段、关联发票和附件内容。附件缺失属于业务问题；附件存在但读取失败时说明未能核验，不得声称申请人未上传。问题结论应指出具体材料、金额或关系，不要求固定句式。

## 固定四项审核

1. 附件完整性：读取各明细预算科目，按下表核对附件。同科目的共用制作清单和照片可在整单范围核对，不要求每行重复上传；字段未解析时，仍需检查当前单据已取得的附件内容，不直接判缺。科目可读但不在表中时，按支付截图和发票检查，不因表外科目单独提示异常。科目本身读不清时说明无法确定适用要求。收款人名称与关联发票销售方一致，且对应关系可信时，按对公支付免支付截图；不能只凭选择了企业支付接口认定豁免。其他必需附件仍需核对。清单盖章、现场定位及照片要求都在本项核对。
2. 发票关联与金额：核对当前单据 OA“关联发票”及发票金额，同一发票去重计入。单据内已关联发票不要求逐行重复挂票，也不额外要求提供发票金额逐行分摊表；发票挂在某一明细行上不等于金额只属于该行，不能直接把整张发票总额与第一行金额不同判为冲突。存在多支付对象、跨单据或重复票据等明确问题时，再按实际对应关系核对，不凭金额相同推断其他单据或附件的归属。仅纸质发票或收据才核对快递单号、是否已传递或邮寄；收据另核对购买方、事项、金额、收款人姓名、身份证号和手机号。没有纸质发票或收据时，不提示该项附加要求，不另设签字栏目。电子发票本身不是问题。
3. 金额孰低核销：列出可信支付金额、发票金额及适用的盖章制作清单金额，按孰低原则形成核销意见。终端形象制作费须核对并说明盖章制作清单总额。已确认对公且免支付截图时，使用申请支付金额与当前单据已关联发票金额核对，申请金额不能写成已实际支付。多张凭证合计须有可信对应关系并排除重复截图；金额比较不设置容差；金额无法确认或存在明确归属冲突时，说明待核实事实，不因缺少逐行分摊信息单独提示异常。已提供材料中的支付失败、重复和金额冲突仍需报告。
4. 支付公司一致：核对报销公司、支付公司、发票购买方是否一致，并说明应选择的实际公司全称支付。无法确认时列出缺失字段或冲突原值，不猜测公司对应关系。收款人与销售方关系属于第一项的支付截图豁免条件，不独立增加审核项。

## 10 类费用科目与附件要求

| 费用科目 | 必需附件 | 专项核对 |
| --- | --- | --- |
| `终端建设费-终端形象制作费` | 发票、广告公司盖章版制作清单、执行后现场定位照片 1 张 | 制作清单内容结合已提供的参考报价单和照片核对数量、样式；参考报价单不是必传附件；清单印章与发票销售方一致；无支付截图时核对收款人姓名与发票销售方一致 |
| `推广费用-物料费` | 发票、制作清单或购买明细、支付截图、制作完成定位照片 | 清单或明细与定位照片一致 |
| `终端建设费-其他` | 发票、支付截图 | 按通用发票和支付对应关系核对 |
| `通路促销-订货会会务费` | 关联申请签报、发票、费用清单、签到表、支付凭据；每个申请不少于 4 张订货会现场多角度全局定位照片 | 逐个申请核对照片数量、全局视角和定位信息，缺少会议材料时明确列出 |
| `推广费用-产品赠品费` | 发票、支付截图 | 按通用发票和支付对应关系核对 |
| `推广费用-试吃品费` | 发票、支付截图、执行试吃定位照片 | 说明照片缺失或定位无法确认的具体情况 |
| `促销员费用-管理费` | 发票、支付截图 | 按通用发票和支付对应关系核对 |
| `促销员费用-激励费` | POS 复核数据表、激励政策（申请签报或签报截图） | POS 表只检查是否上传，不识别表内内容 |
| `促销员费用-统筹福利` | 关联申请签报、发票、支付截图 | 核对签报与当前明细的归属关系 |
| `促销员费用-专项费用` | 发票、支付截图 | 按通用发票和支付对应关系核对 |

不得用文件名、附件顺序、相似金额或日期猜测附件归属。参考报价单只在已提供时参与比对，不是必传附件。豁免支付截图不豁免其他材料和已发现的冲突。

## 签字意见

结构化决定和签字意见均完整保留上述四项，复用公共输出：通过显示 `✅`，明确不符显示 `❌`，证据不足显示 `⚠️`。同一缺口在最相关项说明，其他项只说明受到的实际影响，不复制成多条警告。不再输出仅含问题的清单。

历史 V1/V2 六项审核包保持原始冻结内容，用于回查；新工作进程只处理 V3 四项包，旧包不得直接换版本后继续审核，须重新准备材料。
